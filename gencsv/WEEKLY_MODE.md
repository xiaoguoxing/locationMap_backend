# 按周查询模式说明

## 背景

原始的 7 天滚动窗口模式虽然数据细腻，但查询次数过多：

- **原始模式**：最近 30 天生成 31 个滑动窗口 × 3 个参数 = **93 次查询**
- **按周模式**：最近 30 天生成 5 个自然周 × 3 个参数 = **15 次查询**

按周模式可**减少 84% 的数据库查询次数**，降低业务库压力。

## 使用方法

### 命令行

**最近 30 天（默认）**：

```cmd
01_extract_csv.bat --weekly
```

**指定月份**：

```cmd
01_extract_csv.bat --from 2026-04-01 --to 2026-04-30 --weekly
```

**最近 60 天**：

```cmd
01_extract_csv.bat --days 60 --weekly
```

### Python 直接调用

```python
from gencsv.extraction_service import run_extraction

# 按周抽取最近 30 天
result = run_extraction(
    days_back=30,
    weekly=True,  # 启用按周模式
)

print(f"生成 {result['rangeCount']} 个周区间，共 {result['queryCount']} 次查询")
```

## 日期区间规则

按周模式使用**自然周**（ISO 8601 标准）：
- 每周从**周一**开始，到**周日**结束
- 自动向前对齐到完整的周一
- 最后一周可能不满 7 天（截断到结束日期）

**示例**（2026-04-01 到 2026-04-30）：

```
2026-03-30 (周一) 至 2026-04-05 (周日)  ← 向前对齐到周一
2026-04-06 (周一) 至 2026-04-12 (周日)
2026-04-13 (周一) 至 2026-04-19 (周日)
2026-04-20 (周一) 至 2026-04-26 (周日)
2026-04-27 (周一) 至 2026-04-30 (周四)  ← 最后一周截断
```

## 查询次数对比

| 场景 | 原始模式 | 按周模式 | 减少 |
|---|---|---|---|
| 最近 30 天 | 93 次 | 15 次 | 84% |
| 整月 (30天) | 90 次 | 15 次 | 83% |
| 最近 60 天 | 183 次 | 27 次 | 85% |
| 整月 (31天) | 93 次 | 15 次 | 84% |

## 数据影响评估

### 优点

1. **大幅减少数据库查询次数**：从 93 次降到 15 次
2. **降低业务库压力**：适合生产环境长期运行
3. **数据仍然完整**：所有采样记录都被包含
4. **前端无需改动**：API 和地图逻辑完全兼容

### 权衡

1. **时间粒度变粗**：
   - 原始：每天都有 7 天窗口可查
   - 按周：只有按周划分的 4-5 个区间

2. **日期选择器体验**：
   - 原始：用户可选择任意连续 7 天
   - 按周：只能选择预定义的周区间

### 建议

- **命令行批处理**：推荐使用 `--weekly`，减少手工抽取压力
- **前端隐藏按钮**：生产环境可修改为按周模式
- **未来直连数据库**：按周模式更适合实时查询

## 前端 API 集成（可选）

如需前端隐藏同步按钮也使用按周模式，修改 `api/extraction.py`：

```python
# 修改前
result = run_extraction(days_back=30, range_days=7)

# 修改后
result = run_extraction(days_back=30, weekly=True)
```

重启 API 服务后，前端按钮触发的同步任务将自动按周查询。

## 兼容性说明

- ✅ 所有现有参数仍然有效（`--days`、`--from`、`--to`）
- ✅ 可与 `--single-day` 互斥（不能同时使用）
- ✅ 输出文件格式完全一致
- ✅ Repository 层无需修改
- ✅ 前端地图无需改动

`--weekly` 是**可选**增强功能，不影响现有流程。
