# 供水水质地图可视化系统 — 数据来源与数据处理流程汇报

本文面向客户汇报，系统说明本系统的数据从哪里来、经过哪些处理环节、最终如何得到地图上展示的关键指标。全文按照数据流动的先后顺序，划分为五个步骤：数据采集源头、CSV 数据提取、地图数据加工、地图可视化生成、仪表盘统一展示。

> 📌 重要：本系统由三段式流水线组成 —— `gencsv`（取数）→ `maps`（加工与制图）→ `dashboard`（展示）。三段以中间产物（CSV 文件、HTML 地图文件）解耦，各自独立运行，通过约定的文件命名规则衔接。

## 步骤 1、数据采集源头（数据库与原始字段）

本系统的全部正式数据来源于实验室信息管理系统（LIMS）的 SQL Server 数据库，由取数脚本通过 ODBC 直连查询获得，不依赖任何中间导出文件。

### 1.1 数据库连接

- 数据库类型：Microsoft SQL Server，通过 `ODBC Driver 18 for SQL Server` 连接
- 连接参数集中配置在 `gencsv/setting.ini`，区分测试库与生产库两套配置

数据库连接配置示例（`gencsv/setting.ini`）：

```ini
[DATABASE]
host = 10.66.89.44
port = 1433
database = labworks_wsduat   ; 测试库；生产库为 labworks
username = map
password = ******
```

> ⚠️ 注意：连接串中启用了 `TrustServerCertificate=yes`，连接账号 `map` 为只读取数账号，仅用于查询，不具备写权限。

### 1.2 数据来源表与关联关系

数据通过三张核心表关联查询得到：

| 表名（别名） | 含义 | 关联方式 |
| --- | --- | --- |
| `sample`（`sa`） | 样本主表（样本号、采样点、采样日期、状态、责任方） | 主表 |
| `suserflds`（`suf`） | 样本扩展字段（所属地区、GPS 经纬度） | `LEFT JOIN`，按 `sampno` 关联 |
| `result`（`re`） | 检测结果表（分析项代码、结果值、原始结果值） | `INNER JOIN`，按 `sampno` 关联 |

### 1.3 监测的三项关键水质指标

系统聚焦三项水质指标，分别对应三套 SQL 模板（位于 `gencsv/sqltemplate/`）：

| 指标 | 分析项代码（`acode`） | 单位 | SQL 模板 |
| --- | --- | --- | --- |
| 游离余氯 Free Chlorine | `CL2_FREE_1` | mg/L | `cl2_free_1.sql` |
| 大肠杆菌 E. coli | `ECOLI` | CFU/100mL | `ecoli.sql` |
| 浊度 Turbidity | `TURBY` | NTU | `turby.sql` |

### 1.4 数据筛选（清洗）规则

三套 SQL 模板采用统一的筛选条件，确保取出的都是有效、已校验的合格数据：

- 仅取指定分析项：`re.acode = '对应指标代码'`
- 采样日期落在指定区间：`coldate >= [date_from] AND coldate <= [date_to]`（占位符在运行时替换为真实日期）
- 样本状态必须为已验证或待报告：`current_state IN ('SAMP_VALIDATED','SAMP_REPORT_QUEUE')`
- 结果值与原始结果值均非空，且必须能成功转换为数值（`try_cast(... as float) is not null`），剔除文字型无效值
- 采样点编码限定：`loccode LIKE 'SR-%'` 且包含 `-FC-` 片段（即只统计指定类别的采样点）

> 📌 重要：经纬度在 SQL 中已做防御处理 —— 当 `loc_gps_latitude/longitude` 为空或空串时返回 `null`，否则 `try_cast` 转为浮点数，输出为 `loc_gps_latitude_value` / `loc_gps_longitude_value` 字段，供后续制图直接使用。

## 步骤 2、CSV 数据提取（gencsv 模块）

`gencsv` 模块负责把数据库查询结果导出为 CSV 文件，是整条流水线的取数环节。它提供两种运行方式。

### 2.1 方式一：单次提取（`main.py`）

适用于一次性按固定日期取数。流程为：读取 `setting.ini` 配置 → 归档旧文件 → 按 `[JOBS]` 中列出的 SQL 文件逐个执行 → 输出 CSV 到 `gencsv/output/`。

```bat
> 01_extract_csv.bat
```

该批处理实际执行：

```bat
python gencsv/main.py
```

### 2.2 方式二：按日期范围批量提取（`date_range_runner.py`）

这是日常主力工具，支持按"回溯窗口"批量生成多个日期区间的数据。它读取 `gencsv/sqltemplate/` 下的 SQL 模板，把模板中的 `[date_from]`、`[date_to]` 占位符替换为真实日期后再执行。

常用命令：

```bash
# 最近 30 天，每个窗口回溯 14 天
$ python date_range_runner.py --days 30 --range-days 14

# 指定具体日期区间
$ python date_range_runner.py --from 2026-03-01 --to 2026-03-15

# 每天单独生成一份（按日快照）
$ python date_range_runner.py --days 7 --single-day
```

"回溯窗口"逻辑说明：对区间内的每一天，都向前回溯 `range-days` 天形成一个窗口。例如 `--range-days 14` 时，4 月 16 日对应的窗口是 4 月 3 日至 4 月 16 日（含两端共 14 天），逐日滚动。

### 2.3 提取的技术实现要点（`db_connector.py`）

- 使用 `pyodbc` 连接数据库并执行 SQL
- 通过 `cursor.fetchmany(1000)` 分批读取，避免大数据集一次性载入内存
- 输出 CSV 统一采用 `utf-8` 编码，表头取自查询结果列名

### 2.4 输出文件命名规则

生成的 CSV 文件名遵循统一格式，后续制图与展示环节都依赖此规则解析参数与日期：

```text
{指标名}_{起始日期}_{结束日期}_{时间戳}.csv
```

例如：`cl2_free_1_2026-04-10_2026-04-16_20260518_184254.csv`

### 2.5 旧文件归档（`file_manager.py`）

每次运行前，会扫描 `output/` 目录，凡文件名中 8 位日期早于当天的，自动移动到 `archive/` 目录，保持输出目录整洁。

> ✅ 建议：日期范围、目标库（测试 / 生产）等均通过 `setting.ini` 与命令行参数控制，更换统计周期无需改动代码。

## 步骤 3、地区聚合与坐标补全（数据加工核心）

CSV 提取出的是逐条样本明细。要得到"地图上每个地区的关键指标"，需经过 `maps` 模块的加工，核心由 `district_aggregator.py` 完成。

### 3.1 坐标补全

部分采样点缺少 GPS 经纬度。系统用 `gencsv/missing_gps/district_gps.csv`（记录香港各地区中心点经纬度）按地区名回填缺失坐标，确保尽量多的数据能落到地图上；仍无坐标的样本在制点位图时被过滤。

### 3.2 地区名归一化（映射到香港 18 个行政区）

原始数据中的地区 / 地段名称写法不统一。系统通过两套对照将其归一化到官方 18 个行政区：

- `maps/data/district_mapping.py` 中的 `NEIGHBORHOOD_TO_DISTRICT` 地段 → 行政区映射表
- `maps/data/hk_districts.geojson` 官方 18 区边界中的标准区名

归一化时依次尝试：直接匹配 → 去空格匹配 → 处理 `&` / `and` / `-` 等写法变体，最大限度命中标准区名；命中不了的会作为"未匹配"打印告警。

### 3.3 按指标聚合得到关键数据

不同指标采用不同的聚合口径，这是"关键数据如何得到"的核心：

| 指标 | 聚合方式 | 输出关键字段 |
| --- | --- | --- |
| 游离余氯 / 浊度 | 按区分组求 `平均值 mean`、`最大值 max`、`样本数 count` | 区平均值、最大值、样本数 |
| 大肠杆菌 E. coli | 按区统计 `污染样本数`、`总样本数`、`污染率 contamination_rate`、平均值、最大值 | 污染率（结果 > 0 的样本占比）、平均值 |

> 📌 重要：地图上每个区显示的数值，对游离余氯与浊度是该区所有有效样本的"平均值"，对大肠杆菌额外计算"污染率（结果大于 0 的样本占比）"。这正是从逐条明细到地图关键指标的换算逻辑。

### 3.4 指标着色阈值（颜色分级标准）

聚合后的数值按以下阈值映射为地图颜色（区域分级图 `get_color_for_district`）：

| 指标 | 绿（合格 / 良好） | 橙（偏高） | 深红（高） | 红（异常） |
| --- | --- | --- | --- | --- |
| 游离余氯（mg/L） | 0.2 ~ 1.5 | 1.5 ~ 2.0 | 2.0 ~ 3.0 | < 0.2 或 > 3.0 |
| 浊度（NTU） | ≤ 1.5 | 1.5 ~ 3.0 | 3.0 ~ 10.0 | > 10.0 |
| 大肠杆菌（CFU/100mL） | 等于 0 | — | — | 任意 > 0 |

> ⚠️ 注意：游离余氯采用"双红"设计 —— 余氯过低（< 0.2，消毒不足）与过高（> 3.0）都标红，因为两端都属于不理想状态。

## 步骤 4、地图可视化生成（maps 模块）

加工后的数据由 `maps` 模块绘制为可交互的 HTML 地图，使用 `folium`（基于 Leaflet）库。共生成三类地图。

### 4.1 触发方式

```bat
> 02_generate_maps.bat
```

该批处理依次运行两个脚本：

```bat
python maps/location_mapper.py        :: 生成详细点位图 + 单指标区域图
python maps/multi_param_mapper.py     :: 生成多指标合并区域图
```

### 4.2 三类地图产物

- **详细点位图（detailed）**：由 `location_mapper.py` 的 `plot_map` 生成，每个采样点一个圆点标记，按结果值着色，点击弹窗显示样本号、采样点编码、描述、地区、采样日期、结果值等明细。
- **单指标区域分级图（district）**：由 `choropleth_mapper.py` 的 `create_choropleth_map` 生成，以 18 区边界填色，区中心标注该区平均值，弹窗显示平均值、最大值、样本数。
- **多指标合并区域图（district_all_param）**：由 `multi_param_mapper.py` 生成，按日期区间把游离余氯、大肠杆菌、浊度三项合并到同一张区域图，悬停可同时查看一个区的三项指标。

### 4.3 区域图的制图技术要点（`choropleth_mapper.py`）

- 采用 Shoelace（鞋带公式）计算每个区多边形的面积加权质心，用于放置区数值标签
- 对岛屿、飞地等复杂多边形（如离岛、荃湾、观塘等）提供 `DISTRICT_CENTROID_ADJUSTMENTS` 手动微调，避免标签落到海面或区外
- 地区名同时提供繁体中文对照（`DISTRICT_NAMES_TC`），弹窗中中英文并列显示
- 底图采用 `CartoDB positron`，地图中心固定为香港（22.3193, 114.1694）

### 4.4 地图输出目录

```text
maps/output/detailed/              :: 详细点位图
maps/output/district/              :: 单指标区域图
maps/output/district_all_param/    :: 多指标合并区域图
```

## 步骤 5、仪表盘统一展示（dashboard 模块）

`dashboard` 模块是一个基于 Flask 的 Web 服务，负责把生成好的 HTML 地图统一汇总、检索并在浏览器中展示。

### 5.1 启动方式

```bat
> 03_start_dashboard.bat
```

服务启动后访问：`http://localhost:5000`

### 5.2 后端工作机制（`dashboard/app.py`）

- 扫描 `maps/output/` 下的 `district`、`district_all_param`、`detailed` 三个子目录
- 通过 `parse_filename` 解析每个地图文件名，提取指标、起止日期、时间戳、视图类型等元数据
- 提供接口 `/api/maps`，以 JSON 返回全部可用地图列表与汇总统计（地图总数、各指标数量、日期范围）
- 通过 `/maps/output/<视图类型>/<文件名>` 路由，以 iframe 方式向前端提供地图 HTML

接口返回结构（简化）：

```text
GET /api/maps  →
{
  "success": true,
  "data": [ {指标, 显示名, 单位, 起止日期, 视图类型, url}, ... ],
  "summary": { "total_maps": N, "parameters": {...}, "date_range": {...} }
}
```

> 📌 重要：仪表盘本身不处理任何水质数据，它只读取 `maps` 模块生成的 HTML 文件并组织展示。因此更新数据时，需先跑步骤 2（取数）、步骤 4（制图），仪表盘会自动扫描到新地图。

## 步骤 6、辅助与演示脚本说明

为避免汇报时混淆，需特别说明根目录下另有几个独立的演示 / 调试脚本，它们不属于上述正式流水线：

- `cluster_map.py`：读取根目录 `chlorine_data.csv` 的演示数据（仅含 `id,lat,lon,chlorine` 四列的样例点），生成单张 `chlorine_map.html`，用于快速演示余氯点位图效果。
- `cluster_map_blackspot.py`：读取 `bp_data.csv`（黑点 / 案例点位演示数据），生成 `blackspot_map.html`。
- `debug_*.py`：针对特定地区（如沙田）制图问题的调试脚本。

> ⚠️ 注意：上述脚本使用的是样例 / 调试数据，与正式流水线（数据库 → gencsv → maps → dashboard）不是同一套数据来源，汇报中应明确区分，避免误把演示数据当作生产数据。

## 总结

本系统是一条"数据库取数 → CSV 中间文件 → 地区聚合加工 → 可交互地图 → Web 仪表盘"的完整数据流水线：

1. 数据来源是 LIMS 的 SQL Server 数据库，经严格筛选（指标代码、样本状态、数值有效性、采样点编码）取出游离余氯、大肠杆菌、浊度三项有效样本。
2. 关键展示数据由"按香港 18 区聚合"得到 —— 余氯 / 浊度取区平均值与最大值，大肠杆菌额外计算污染率，并按统一阈值映射为地图颜色。
3. 三段模块以约定的文件命名规则解耦，更新数据只需按步骤顺序重跑，无需改动代码。

> 📌 备注：本项目当前正在进行后端（Spring Boot）重写，本文所述为现有 Python 流水线的实际数据处理逻辑，可作为重写后功能对齐的业务基线。
